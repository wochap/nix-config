# Email setup

Mails are saved to `~/Mail` folder

### Stack

- Neomutt:
  email TUI (with notmuch virtual folders for lieer accounts)
  - Mailcap:
    define mimetypes for email content
- Mailnotify:
  notifies when mail has arrived in your mail directory
- Goimapnotify:
  notifies you of new e-mails coming in (IMAP IDLE, used through the home-manager `services.imapnotify` module)
- Lieer:
  synchronizes gmail accounts (labels <-> notmuch tags) via the Gmail API
- Mbsync:
  synchronizes mailboxes of non-gmail accounts (only enabled when an account uses it)
- Notmuch:
  mail indexer, used by lieer and neomutt virtual folders
- msmtp:
  simple and easy-to-use SMTP client with fairly complete sendmail compatibility
- Offlinemsmtp:
  allows you to use msmtp offline by queuing email until you have an internet connection
- smtp:
  protocol to send mails

### Setup

#### Gmail

Lieer syncs through the Gmail API using OAuth (lieer ships with public
OAuth credentials, so no Google Cloud project is needed), while
goimapnotify still watches IMAP and needs an app password.

1. Enable 2FA auth in your google account
1. In Gmail > Settings > Forwarding and POP/IMAP, enable POP and IMAP
1. Generate a [app_password](https://support.google.com/accounts/answer/185833?hl=en), go to [Google Account](https://myaccount.google.com/) > Security > 2-Step Verification > App passwords
1. Add a file in `<NIX_CONFIG_PATH>/secrets/mail/<BOX_NAME>`, and paste the password/token/app_password (e.g. 16 digits)
1. Authorize lieer once per account (opens the browser OAuth flow):

   ```sh
   cd ~/Mail/<BOX_NAME>
   gmi auth
   ```

1. Run the first sync (takes a while on large mailboxes). Stop mailnotify
   for the duration, otherwise every pulled mail triggers a notification:

   ```sh
   systemctl --user stop mailnotify
   email-sync   # or: gmi sync
   systemctl --user start mailnotify
   ```

1. Optional, apply the initial tags directly in the notmuch database too
   (the database copy can override the config file during lieer pulls):

   ```sh
   notmuch config set --database new.tags unread inbox
   ```

#### Other providers (non-gmail)

Set `sync = "mbsync"` in the account file. Mbsync mirrors the IMAP
folders to maildir and notmuch indexes everything after each sync
(timer `postExec`), on new-mail pushes (`goimapnotify` onNotify) and
through `email-sync`. Notmuch search, virtual folders, the bar badge
and notmuch.nvim all work across both sync methods — one database.

Note: `notmuch new` initially tags every new file `unread inbox`,
regardless of the folder it landed in; maildir flag sync corrects
`unread` from the `\Seen` flag, but refine folder-based tagging (afew or
a post-new hook) if the noise bothers you.

#### Migrating an account from mbsync to lieer

Lieer stores everything in a flat maildir (`~/Mail/<BOX_NAME>/cur`) with
labels synced as notmuch tags — the mbsync folder layout
(`INBOX`, `[Gmail]/Sent Mail`, ...) is not used anymore.

1. Wipe the old mbsync data of the account: `rm -rf ~/Mail/<BOX_NAME>/*`
1. Follow the Gmail setup steps above
1. Update `~/Sync/.config/neomutt/mailboxes`: remove the maildir entries of
   the migrated account (its virtual folders are generated by nix)

### Extras

- Neomutt keys: `Ctrl-s` ad-hoc notmuch query as virtual folder, `f` edit
  tags, `D` trash tag, `A` archive (remove inbox tag), Tab in To:/Cc:
  completes contacts from the whole mail history (`notmuch address`)
- The bar shows a mail badge with the unread inbox count
  (`shell-mail`, quickshell `SMail`)
- notmuch.nvim (nvim): reads the same notmuch db. Upstream hardcodes the
  send command, so a fork with a `send_cmd` option is used — configure it
  with `send_cmd = { "offlinemsmtp", "--" }` so nvim sends go through the
  offlinemsmtp queue too (offline sends get delivered once online)
